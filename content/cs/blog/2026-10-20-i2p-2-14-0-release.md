I2P 2.14.0 (API 0.9.71) bylo vydáno 2026-10-20. Toto vydání posiluje zabezpečení routeru i přibalených aplikací, přináší velkou sadu vylepšení i2psnark a opravuje problémy se spolehlivostí streamování a tunnelů.

Jako obvykle doporučujeme aktualizovat na toto vydání. Nejlepší způsob, jak udržet zabezpečení a pomoci síti, je provozovat nejnovější vydání.

## Zabezpečení

**Router**

- Operace AES a porovnávání EdDSA podpisů nyní probíhají v konstantním čase ([73819404c](https://github.com/i2p/i2p.i2p/commit/73819404c), [6440d5f16](https://github.com/i2p/i2p.i2p/commit/6440d5f16))
- Opraveno čtení mimo povolené hranice při parsování garlic clove a nedostatečně velký buffer pro NTCP2 zprávu 3 ([67b2f7327](https://github.com/i2p/i2p.i2p/commit/67b2f7327), [db3cd60f1](https://github.com/i2p/i2p.i2p/commit/db3cd60f1))
- Tunnely zahazují duplicitní fragmenty a omezují mapu pro znovusestavení fragmentů ([8af94b9e4](https://github.com/i2p/i2p.i2p/commit/8af94b9e4), [4c3d10c12](https://github.com/i2p/i2p.i2p/commit/4c3d10c12))
- Menší opravy robustnosti v NetDB, NTCP a zpracování datagramů

**i2ptunnel**

- HTTP proxy blokuje požadavky na privátní, loopback a link-local IPv4 adresy ([3aef97a9d](https://github.com/i2p/i2p.i2p/commit/3aef97a9d))
- Opraveno obejití autentizace proxy pomocí downgrade na SOCKS 4/4a ([ff63e0cdf](https://github.com/i2p/i2p.i2p/commit/ff63e0cdf))
- Tunely HTTP serveru odstraňují CR z hlaviček; řetězce autentizace proxy se již nezaznamenávají do logu
- Opravy escapování výstupu v celém Hidden Services Manager

**i2pcontrol**

- Ochrana pomocí CSRF tokenu, bezpečnostní hlavičky pro JSON a zpoždění při neúspěšné autentizaci ([9a1c56f35](https://github.com/i2p/i2p.i2p/commit/9a1c56f35), [e79e4949d](https://github.com/i2p/i2p.i2p/commit/e79e4949d), [8fbfb70fb](https://github.com/i2p/i2p.i2p/commit/8fbfb70fb))
- Odstraněno použití výchozího hesla `itoopie` jako záložní možnosti

**i2psnark a Addressbook**

- Zpevněné parsování bencode (limit rekurze, odmítání duplicitních klíčů) a kontroly path traversal
- Addressbook nyní při aktualizaci kontroluje nesoulad destination ([a884b9093](https://github.com/i2p/i2p.i2p/commit/a884b9093))

## i2psnark

- **Magnet odkazy:** všechny trackery se nyní používají a ukládají, navíc podpora parametrů názvu `dn` a velikosti `xl`
- **Trackery a DHT:** záložní UDP tracker, chytřejší časování announce, třídění slovníků podle specifikace, komprimované UDP a DHT zprávy
- **Výkon:** nižší spotřeba paměti a rychlejší hashování při vytváření nebo rechecku torrentů; vyladěné throttlování požadavků, pipelining a timeouty
- **UI:** volné místo na disku se zobrazuje a kontroluje při přidávání torrentů, ovládání audio playlistu, živé aktualizace se obnoví, když je karta opět viditelná
- **Opravy:** priority souborů se už neztrácejí po kontrole při startu ([GH #170](https://github.com/i2p/i2p.i2p/commit/83e4f326f)), extrakce atributů metainfo, NPE při handshake rozšíření
- Základ pro BitTorrent v2 (zatím není uživatelsky dostupné)

## Streamování a transport

- Opravy synchronizace streamingu v cestách retransmit a ack, plus ladění slow start a reset ([061d4e3f6](https://github.com/i2p/i2p.i2p/commit/061d4e3f6))
- Tunnely pravidelně používají 5-slotové zprávy pro stavbu tunnelu
- Nová explicitní volba force-IPv6, podpora Docker bridge se připravuje
- SAM: opraveny subsessions DG2/DG3 ([d2392ae9b](https://github.com/i2p/i2p.i2p/commit/d2392ae9b))
- I2CP: nové session API `discardMessage()`

- Docker: Debian Trixie, OpenJDK 21, Ant 1.10.18, commit SHA orazítkován v buildech
- Opravy buildu pro izPack 5.2.6, gettext 1.0 a Gradle
- Aktualizace GeoIP, Tor blocklistu, seznamu trackerů a překladů
